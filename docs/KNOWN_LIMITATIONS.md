# 已知限制（MVP 0.1 / M6）

诚实列出当前边界，避免把“未做”包装成故障。

## 产品

- 无 Steam 登录、好友关系与游戏库交集。
- 无移动端、推送与组队社交。
- 无用户生成评论/社区帖。
- 自然语言 AI 默认关闭；无 Key 时返回确定性 `ai_status=fallback`。
- 四分区在真实数据不足时允许少于 20 条，并如实展示空态/早期数据。

## 数据

- 商店搜索多人分类是易变适配器，不构成深度联机画像。
- **候选发现排序（2026-08 治本基线）**：**新游不可能都有高评价**；曾用 `Reviews_DESC` 作发现主排序时，刚发售、评价少/为零的联机作系统性漏检（典型如派对新游《机械狂欢》）。`store-search-0.2` 起默认 `Released_DESC` 止血。评价只应作排序/解释信号，不作进池硬门槛。**后续算法优化**（双通道合并、地区参数、新游保送配额、评价分层）见 [RECOMMENDATION.md](RECOMMENDATION.md) §13.5。
- 熟人联机高影响字段（自建服、私人房、服务依赖）依赖黄金集与人工校正。
- 典型局时长覆盖仍低，未知时显示未知。
- 价格区域默认 `CN/schinese`；历史 US/USD 快照不代表中国区完成。
- 日历/Demo 依赖易变商店字段 + 人工回退。

## 推荐与校准

- 黄金矩阵评估器已经存在，但仓库没有可声明为生产有效的 200+ 人工相关性矩阵，当前线上权重未由玩家标注自动冻结。
- `recommendation_index` 仍是当前请求实际返回页/窗口内的中位秩指数，不是整分区百分位或接受概率；分页/窗口变化可能改变指数。曝光位置校正、isotonic calibration、影子流量和分阶段放量尚未实现。
- 推荐 run/item、反馈事件、公开 `exposure/detail_open/steam_click/play_intent` 接口及 Web 上报已接线；但曝光仍以卡片挂载代理而非 viewport 确认，Demo 跳转也没有独立枚举，因此不能声称完整线上漏斗归因率。
- 反馈 Storage 已保留 sentiment、ownership 与多个 reason 维度，但公开 API 仍一次提交一个 legacy `type`，尚无跨游戏的 90 天半衰期偏好学习。
- Feed 已公开卡片级 `reason_evidence[]` 与五组 `feature_freshness`，但尚无逐句证据映射和逐卡解释完整性保证；低覆盖特征必须继续显示未知/资料不足。
- 玩家 Feed 的精确同分已接入稳定用户每日哈希，AppID 仅作哈希碰撞后的技术兜底；无请求身份的内部兼容入口仍按 AppID。公开指数继续让精确相关性同分共享同一值，不制造假精度。

## 技术

- 单主 SQLite，无 active-active、无网络文件系统部署。
- 服务端默认 loopback；HTTPS 由外部反向代理承担。
- Windows 服务通过 WinSW 托管控制台进程，而非进程内 SCM 实现。
- 桌面自动更新与代码签名策略已文档化，**未**在默认 CI 启用私钥签名（需负责人授权与证书）。
- macOS 以原生 runner 构建/APP smoke 为证据，不跑 `tauri-driver` GUI E2E。
- 性能门槛以本地集成测试与 CI 为目标硬件；生产压测需单独环境。

## 合规

- 隐私政策见 [PRIVACY.md](PRIVACY.md)；遥测默认最小且可关闭（当前 MVP 不以第三方分析 SDK 为依赖）。
- 第三方许可清单由脚本生成，UNKNOWN 行须在商店分发前清理。
- Steam 品牌与素材使用见 [STEAM_BRAND_REVIEW.md](STEAM_BRAND_REVIEW.md)；未获批不得使用受保护徽标。

## 运维

- 备份是运维责任；未配置定时任务时不会自动异地备份。
- 限流默认按设备/会话与 IP；错误开启 `MPGS_TRUST_PROXY_HEADERS` 会导致限流键被伪造。
